## Scope and API

New lib/portfolio_construction namespace, dedicated test and scripts/d0113_demo.py only. Consume an immutable desired D0112 PortfolioRequest, already encoding explicit requested initial-capital weights INCLUDING entry costs and desired cash. Validate the entire desired request using public evaluate_portfolio_risk before selection; its declared constraint breaches are allowed as construction inputs, but invalid/rejected constituents must never disappear through filtering. No ranking by forecast, return, probability, optimizer, stock selection, trades, FX, shorts or leverage.

Construction request is immutable/hash-sealed: requestID, desired request, unique explicit priority tuple of every desired positionID exactly once, allocation_quantum, policy_ref, policy_available_at, calculated_at. Priority must be caller specified and complete (empty only for all cash). Explicit priority determines all allocation competition; no silent sorting by ID or score to choose winners. Construction calculated_at>=desired.calculated_at, all timestamps aware, policy_available_at<=desired.cutoff.

Quantum is finite Decimal exactly 10^-n for n integer0..12 (1,0.1,...1e-12), validated by exact rational equality, not normalized under caller Decimal context. Weights and caps are exact Fraction(Decimal) values. Output allocation is integer quantum units, rounded DOWN so it never exceeds a desired weight/cap/cash reserve. Emit exact terminating Decimal via tuple/string construction rather than rounded arithmetic. All remaining capital becomes cash; no redistribution of reductions and no filling an unrequested holding. Preserve at least max(desired cash, policy minimum_cash). No entry/exit costs are subtracted again.

## Allocation rule

Initialize available capital=1-max(desired.cash, minimumcash). Walk explicit priority:
allocation_i=floor_to_quantum(max(0,min(desired_i, remaining_company_limit, remaining_sector_limit, remaining_available_capital))).
After each allocation consume company/sector/capital capacity, aggregating same-company positions. Exact rational arithmetic, not rounded constraints. A zero allocation is omitted from resulting D0112 positions but retained in per-position audit. Record desired/allocated/reduction and binding policy, priority rank, and explicit zero/reduction reason (grid, company, sector, cash/budget) sufficient to reproduce the decision. Returned audit order is priority order; holdings order canonical by ID via public D0112 builder. Reorder desired input through its public canonical builder must not change result for the same priority; changing explicit priority may legitimately change allocation and hash.
